## Что подать на вход

Одна строка — одна выдача. Колонки можно назвать иначе: задайте соответствующие аргументы.

| Параметр | Что должно быть в колонке |
|---|---|
| `id_col` | Уникальный непустой ID заявки |
| `group_col` | Значения нужного разбиения: квартал, месяц, версия, кампания или другая группа |
| `raw_score_col` | Чистый исходный скор **итоговой dub_23** до внешней калибровки, числовой |
| `pd_col` | Калиброванный PD той же заявки и той же модели, число от 0 до 1 |
| `target_col` | Основной таргет 30@4: 1 — дефолт, 0 — недефолт, NA — неизвестный исход |
| `segment_flag_cols` | Три колонки флагов 0/1: ровно один активный сегмент на заявку |

`reference_value` и `comparison_value` — **два разных значения `group_col`**, без преобразования в даты. Например, для целочисленных групп передайте `1` и `2`, а не строки `"1"` и `"2"`. Слова `all`, `reference`, `recent` тоже допустимы как обычные значения исходной колонки.

Функция сама не создаёт кварталы или месяцы. Если нужно разбиение по кварталам:

```python
import pandas as pd

df = df.copy()
df["quarter"] = pd.to_datetime(df["issue_dt"]).dt.to_period("Q").astype(str)
```

Если уже есть нужная колонка, просто передайте её имя. `group_order` задаёт порядок всех групп на графике динамики; для кварталов вида `2025Q4` можно передать `sorted(df["quarter"].dropna().unique())`. Он должен содержать все используемые группы, без повторов. Дополнительные значения без данных отображаются как пропуски. Без `group_order` берётся порядок ordered categorical, иначе — первого появления в данных. Динамика по неупорядоченным категориям не означает временной тренд.

## Если сегмент хранится одной колонкой

Вместо `segment_flag_cols` задайте `segment_col` и список трёх допустимых значений:

```python
result = plot_dub23_calibration(
    df,
    group_col="quarter",
    reference_value="2025Q4",
    comparison_value="2026Q1",
    segment_col="calibration_segment",
    segment_order=[
        "sum_request_less_500",
        "sum_request_500_1000",
        "sum_request_more_1000k",
    ],
    group_order=sorted(df["quarter"].dropna().unique()),
)
```

Для сегментов `A/B/C` передайте `segment_order=["A", "B", "C"]`. Не передавайте одновременно `segment_col` и `segment_flag_cols`. `segment_labels={...}` позволяет задать короткие подписи на картинках. Для трёх флагов `segment_order`, если указан, задаёт соответствующие имена сегментов в порядке `segment_flag_cols`. По умолчанию имена сегментов совпадают с именами флагов. Пороговые суммы и единицы из названий флагов не выводятся: используются ваши готовые сегменты.

## Фильтрация и важные настройки

- Остаются все bad и good с известным таргетом, конечными raw/PD и непустой группой. NA таргета не превращается в 0. Выдачи не фильтруются по уровню риска. Внутри одной заявки нужны только выходы dub_23.
- При необходимости передайте `date_col="issue_dt", max_issue_date="2026-04-30"`. Это дополнительный включающий cutoff по дате выдачи, не колонка группировки. Без cutoff вызревание определяется наблюдаемым таргетом. У квартала после фильтрации могут остаться не все месяцы — это видно по объёмам.
- Дубли/NA ID, некорректный таргет, PD вне [0,1], неоднозначный/неизвестный сегмент вызывают ошибку. Неизвестные сегменты не присваиваются автоматически.
- `higher_score_higher_risk=True` означает, что больший raw — больший риск. Если исходный скор направлен наоборот, передайте `False`. Больший PD всегда считается большим риском.
- `cluster_col="client_id"` включает bootstrap по клиентам, если у одного клиента несколько выдач. `App_id` всё равно должен быть уникален. Без него Gini bootstrap парный, стратифицированный по таргету.
- `bootstrap_iterations` — число повторов CI; для быстрой отладки можно 20–50, для финального результата, например, 500. `random_state` делает результат воспроизводимым.
- `min_defaults=30`, `min_goods=30` помечают малые срезы через `reliable_size` и `result["messages"]`; они не исключают строки из расчёта.
- `scatter_max_goods=3000` ограничивает только число нарисованных недефолтов. **Все дефолты сохраняются на рисунке. Ранги, метрики и пары считаются на полной выборке до прореживания.**

## Что возвращается

`result["figures"]` — четыре объекта Matplotlib Figure, которые можно отобразить отдельно:

```python
display(result["figures"]["rank_migration"])
display(result["figures"]["rank_shift_timeline"])
display(result["figures"]["segment_pairs"])
display(result["figures"]["raw_pd_maps"])
```

1. **rank_migration:** два scatter для `reference_value` и `comparison_value`. X — процентиль риска по raw, Y — по PD; цвет — сегмент, X-маркер — дефолт. 100% — наибольший риск. Ранги считаются **внутри каждого значения group_col по всем сегментам вместе**, а не внутри сегмента. Равные скоры получают средний ранг. Выше диагонали — риск повысился в общем рейтинге; ниже — понизился.
2. **rank_shift_timeline:** сверху медиана сдвига ранга по сегментам и диапазон 25–75% сдвигов клиентов; снизу `Gini(PD)−Gini(raw)` с paired CI по всем группам. Верхняя полоса — разброс клиентов, **не доверительный интервал**. Подписаны n и число дефолтов. Порядок задаёт `group_order`; функция не выдумывает промежуточные данные.
3. **segment_pairs:** две направленные матрицы 3×3. Строка — сегмент дефолта, столбец — сегмент недефолта. Красное — ухудшение Gini, синее — улучшение. Число в п.п. — вклад ячейки в общий разрыв; ↑/↓ — количество улучшенных/ухудшенных пар, включая переходы через ties. Во всех девяти ячейках один общий знаменатель `n_bad × n_good`; поэтому **сумма девяти вкладов точно равна Gini(PD)−Gini(raw) данной группы**. Нет пар — серая ячейка. Количества считаются точно, без семплирования пар; отдельные CI ячеек не оцениваются.
4. **raw_pd_maps:** наблюдаемое преобразование raw→PD по сегментам с одинаковыми осями в двух группах. Линии — медианы по raw-бинам, построенным только на reference. Это не формула calibrator. Отличие облаков/линий само по себе не доказывает обновление calibrator: состав внутри бинов и поддержка исходных скоров тоже могут меняться.

Если в пределах группы и сегмента используется одна строго возрастающая функция калибровки, перестановок внутри сегмента не будет. Если calibrator менялся **внутри квартала**, внутри сегмента квартала возможны перестановки между версиями/месяцами; это не ошибка расчёта. Матрицы не восстанавливают историю сплитов CatBoost: они показывают изменение рейтинга после внешней калибровки.

`result["tables"]`:

| Ключ | Содержимое |
|---|---|
| `rank_movements` | Все использованные заявки; `_cal_group`, `_cal_segment`, ориентированный `_cal_raw`, `_cal_pd`, ранги и `_cal_rank_shift` |
| `cohort_audit` | Число исходных/использованных строк и исключений по каждой группе, включая NA группы |
| `rank_summary` | Объём сегмента, число дефолтов, медиана/IQR сдвига, доли поднявшихся/опустившихся клиентов |
| `gini_by_segment` | Gini raw/PD, разница и CI, проверка монотонности; `segment="__all__"` — все сегменты вместе |
| `segment_pairs` | Точные исправленные/испорченные пары, 9 типов переходов, чистые pair units и вклады в Gini |
| `raw_pd_bins` | Наблюдаемые raw/PD в reference-бинах для каждой группы и сегмента |

Дополнительно возвращаются `messages` (малые срезы/порядок), `group_order`, оба выбранных значения и `saved_files`. В исходный `df` функция ничего не записывает.
